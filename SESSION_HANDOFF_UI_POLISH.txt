What changed in the 2026-06-10 forms reliability pass
-----------------------------------------------------
The user reported that VBA was showing an error in frmUnicodeCleanup. VBA was
stopped in the Unicode cleaner error handler on an Application.Undo line. The
suite now avoids calling Word Undo from inside cleanup error handlers.

Changes made:

- frmUnicodeCleanup now uses UnicodeChar(codePoint) so high Unicode values such
  as U+FEFF are built safely in VBA.
- All cleanup forms with RunErr handlers were changed to capture the original
  error number/description first, close the custom undo record safely, and show
  a single Cleanup Error message.
- Direct Application.Undo calls were removed from cleanup error handlers. The
  message now tells the user to use Word's normal Undo command (Ctrl+Z) after
  closing the message if rollback is desired.
- The installed .docm was missing frmPunctuationCleanup even though the source
  and launcher expected it. That form was recreated in the .docm from
  src\forms\frmPunctuationCleanup.bas, its expected controls were created, and
  the document was saved.
- modCleanupSuiteInstaller in the .docm was refreshed from the rebuilt
  VBA_Cleanup_tool.txt so rerunning the installer does not reintroduce the older
  form code.

Crash/reset mitigation added 2026-06-10
---------------------------------------
The user reported that Word closed or reset after running a tool. Windows Event
Viewer showed real WINWORD.EXE crashes in wwlib.dll with
OFFICE_MODULE_VERSION_MISMATCH entries attached to CleanupSuite_Workspace.docm.

Likely cause: tools were saving/stamping custom document properties on the same
.docm that hosts the running VBA project. When the active document is also
ThisDocument, saving or changing document properties while code is running can
leave Word/VBA in a stale module-version state.

Change made:

- modCleanupHelpers.bas now has IsRunningInMacroHostDocument().
- GuardBeforeCleanup skips silent auto-save when ActiveDocument is the macro
  host document.
- MarkCleanupStart and MarkCleanupEnd exit immediately when ActiveDocument is
  the macro host document, so they do not add/delete custom properties or save
  the host while suite code is running.
- VBA_Cleanup_tool.txt was rebuilt and the installed .docm's modCleanupHelpers
  and modCleanupSuiteInstaller were synced from source.
- A clean close/reopen/compile/save cycle was run after the change.

Important behavior note:

The suite should be run against a normal target document whenever possible, not
against CleanupSuite_Workspace.docm itself. If testing against the macro host is
unavoidable, the new helper guard prevents the suite from stamping/saving the
host during cleanup.

Known caution
-------------
Do not assume a full rerun of InstallCleanupSuite is currently smooth. It may
show a blocking Word/VBA dialog. If continuing from a fresh session, inspect the
dialog visually or use a careful, module-aware install flow before replacing
